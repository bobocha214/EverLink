## Gradle 构建报错修复 (zip END header not found)
- 原因：`~/.gradle/wrapper/dists/gradle-9.1.0-all/...` 的压缩包下载不完整（缺 EOCD 记录）。
- 解决：删除损坏的 `gradle-9.1.0-all.zip` 及 lock 文件；将 `android/gradle/wrapper/gradle-wrapper.properties` 的 distributionUrl 改为腾讯镜像 `https://mirrors.cloud.tencent.com/gradle/gradle-9.1.0-all.zip`（中国大陆下载更快更稳）。
- 另：Gradle 守护进程残留锁导致 `buildLogic.lock` 冲突，需 `taskkill /PID <pid> /F` 并删除锁文件后重跑。

## EverLink 功能开发：Modbus TCP + MQTT 工具
- 项目原为 Flutter 计数器模板，已改造为「设备调试工具」，支持协议扩展。
- 新增依赖：`modbus_client`(1.4.5)、`modbus_client_tcp`(1.2.3)、`mqtt_client`(10.11.11)。注意 `modbus_client_tcp` 需单独添加，前者不依赖后者。
- 架构：
  - `lib/models/`：protocol_type、connection_config、modbus_models、mqtt_models
  - `lib/protocols/`：device_protocol(抽象基类 + DeviceConnectionState 枚举)、modbus_tcp_protocol、mqtt_protocol、protocol_registry(注册表，扩展新协议只需 register)
  - `lib/services/connection_manager.dart`：ChangeNotifier 统一管理连接生命周期，并 `export device_protocol` 供 UI 使用 DeviceConnectionState
  - `lib/ui/`：home_page（协议选择）、modbus_page（线圈/寄存器读写）、mqtt_page（订阅/发布）、widgets/connection_panel
- 注意点：自定枚举 `ConnectionState` 与 Flutter 的 `ConnectionState`（async.dart）冲突，已改名为 `DeviceConnectionState`。`modbus_client` 多写线圈 PDU 长度处理有偏差，故 writeMultipleCoils 改为逐点单写。
- 验证：`flutter analyze` 无 error；`flutter build apk --debug` 成功；`flutter test` 通过。

- 另修：移除 session_manager/modbus_page/mqtt_page 多余 protocol_type 导入；history_page 双下划线 lint；withOpacity→withValues、DropdownButtonFormField value→initialValue 等 deprecation。

## Modbus 文案与连接诊断（22:54）
- 需求：UI 中「单元 ID」改名为「从站 ID」（Modbus 术语 Slave/Unit ID）。已改 modbus_page 的 labelText + connection_config 注释。
- Modbus 仍连不上：排查发现底层库 `modbus_client_tcp` 的 connect() 在失败时不抛异常、只返回 false，吞掉真实 SocketException，导致报错无信息量。
- 新增诊断探针：modbus_tcp_protocol.dart 的 `_probeError` / `_humanizeSocketError`，连接失败时做裸 Socket.connect 探活并把错误翻译成中文（拒绝连接/连接超时/网络不可达/无法路由/权限拒绝/域名解析失败），通过 ConnectionPanel 的 lastError 显示。
- 另：modbus_page IP 输入框加 hint「模拟器连电脑设备请填 10.0.2.2」——这是最常见的连不上原因（127.0.0.1 在模拟器里指向自身而非电脑）。
- 验证：flutter analyze 全绿。仍连不上时用户应按界面提示的实际错误原因自查网络/IP/防火墙，或贴出错误文字进一步定位。

## 交互重构 + Bug 修复（23:3x）
- 修复「状态显示已连接但读取报 Modbus 未连接」bug：根因是 `_requireClient` 用底层 socket 的 `isConnected` 判断，而 UI 用协议自身 `_state`；socket 被静默关闭后两侧不一致。改 `_requireClient` 以协议 `_state` 为权威判断；`_check` 在收到 `connectionFailed` 时把状态同步为 disconnected 并给出明确提示（库 send() 内部会自动重连，连得上就能读到）。
- 连接管理器生命周期：页面不再 `dispose()` 由 SessionManager 持有的 ConnectionManager（否则重开页会拿到已释放实例）；页面改为监听 manager 状态变化以实时刷新 UI（连接/断开按钮、读取按钮可用态）。modbus_page / mqtt_page 均加 listener，dispose 时 remove + 取消自动刷新定时器。
- 添加设备流程重构：新增 `lib/ui/widgets/add_device_sheet.dart`，选协议→填名称与连接参数→**保存不自动连接**，首页 FAB 调用。IP/Broker 地址允许留空（移除必填校验），设备页手动连接/断开。
- Modbus 页新增「自动刷新（实时读取）」开关：每 2 秒轮询当前读取项；自动刷新产生的读取不写历史（避免刷屏，_execute 加 log 参数）。
- 历史记录页重构：按「操作类别（连接/数据/消息）+ 设备」双维度筛选，聚焦数据内容；HistoryService 改为继承 ChangeNotifier 以支持实时刷新。
- 「我的」页重构：渐变头部卡 + 设备/在线/历史实时统计 + 分区（已支持协议/数据与存储/关于）。
- 验证：flutter analyze 全绿（EXIT=0）。Windows 符号链接构建错误按用户要求未处理。
